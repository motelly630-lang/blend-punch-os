# 배운 것 반영 (os-learn)

원칙의 출처는 대표님 지시 [[PF-003]]. 이 스킬은 **판단·분류·기록**만 하고, 실제 저장은
기존 도구(`os-mem`, 각 스킬 파일, `CLAUDE.md`)에 맡긴다. 기계 점검은 `.claude/lib/learn.py`.

## 0. 읽을 수 있는 것만 근거로 쓴다

| 근거 | 어디 | 한계 |
|---|---|---|
| 지금 대화 | 현재 컨텍스트 | 압축됐으면 요약만 남는다. 다른 세션 대화는 **읽을 수 없다** |
| 수정 저널 | `.claude/state/journal-<세션>.jsonl` | Write/Edit 만 기록. **셸로 고친 파일은 빠진다** → git 으로 보완 |
| git | `git log --since` · `learn.py metrics` | 무엇이 언제 바뀌었나. 왜 바뀌었는지는 커밋 메시지 수준 |
| 기록 | `changelog/` · `LEDGER.md` · 운영 로그 | 사람이 적은 만큼만 |

지난 세션은 저널·git·changelog 로만 본다. "대화를 기억한다/자동으로 학습한다"고 말하지 않는다.

## 1. run — 순서

1. **점검**: `python3 .claude/lib/learn.py pending` · `lint` 결과를 본다.
2. **후보 찾기** (§2 신호). 사례마다 증거를 한 줄로 적는다 (커밋·로그·대표님 발언 인용).
3. **목적지 분류** (§3) → **기존 것 검색** (§4) → 보완 or 신규 or 버림.
4. **후보표를 대표님께 보여준다** (§5 형식). 아래 "바로 적용" 조건에 맞는 것만 먼저 적용하고,
   나머지는 승인 후 적용한다.
5. **적용 + 원장 기록** (§6). 적용 1건 = 원장 항목 1개. 원장 하단 「검토 기록」에 이번 세션을 한 줄 남긴다
   (반영할 게 없어도 남긴다 — 그래야 `pending` 알림이 꺼진다).
6. **검증** (§7) → **보고** (§9).

바로 적용 가능: 사실 정정(수치·경로), 조건이 좁고 근거가 확인된 한두 줄 추가, 새 검사 스크립트,
원장·평가 문서. **먼저 확인**: 기존 지침의 큰 덮어쓰기·삭제, 전역 `~/.claude/CLAUDE.md` 수정,
새 에이전트, 새 훅·자동 실행, 외부 전송, 비용이 드는 설정(모델 호출 훅 등).

## 2. 개선 후보를 잡는 신호

| 신호 | 최소 조건 | 예 |
|---|---|---|
| 대표님이 결과를 **고치거나 지적** | 1회로 후보 | "404 나와" (2026-09-24) |
| 실패의 **원인과 해결이 확인됨** | 재현·로그·테스트로 확인 | tojson 따옴표로 속성 끊김 |
| 대표님이 **같은 설명을 반복** | 이 대화 안 2회, 또는 기존 기록과 겹침 | — |
| 대표님이 **원칙을 명시** | 1회로 충분 (명시이므로) | [[PF-003]] |
| **같은 절차를 반복** 수행 | 2회 이상 (이번 + 기록된 과거) | 배포 → 확인 |
| 기록이 **현실과 달라짐** | 파일·명령으로 확인 | "테스트가 없다" (실제 90건) |

**버린다:** 일회성 요청, 확인 안 된 추측, 작업 결과에 영향 없던 사소한 실수, 코드·git 에서
바로 읽히는 사실. 버린 것도 원장에 `rejected` 로 이유와 함께 한 줄 남긴다 (같은 후보 반복 방지).

## 4. 보완할까, 새로 만들까

1. 검색: 스킬 description(`grep -l <키워드> .claude/skills/*/SKILL.md ~/.claude/skills/*/SKILL.md`),
   `/os-mem find`, `CLAUDE.md`.
2. **보완**: 같은 트리거·같은 작업 대상이 이미 있으면 그 파일에 조건부 항목으로 추가한다.
3. **신규 스킬**은 다음을 **모두** 만족할 때만: 기존 스킬과 트리거가 겹치지 않는다 · 절차가 3단계 이상 ·
   2회 이상 쓰였거나 대표님이 명시적으로 요청했다. 1회뿐이면 `proposed` 로 두고 승격 조건을 적는다.
4. **에이전트**는 독립 맥락이 이득일 때만 (읽기 전용 검토, 긴 조사). 절차만 필요하면 스킬로 충분하다.

새로 만들거나 크게 고친 스킬은 본문에 5가지를 갖춘다:
**사용 조건 / 입력 / 작업 순서 / 완료 조건 / 검증 방법.** 프론트매터에 `metadata.updated` · `review_after`.

## 5. 후보 카드 (대표님께 보여주는 형식)

```
IM-00N  [명시|추론]  신호: <§2 중 하나>
  사례   : <무슨 일이 있었나 — 커밋/로그/발언 인용>
  적용 조건: <언제만 적용되나 — "모든 작업"으로 넓히지 않는다>
  목적지 : <파일> (보완|신규|버림)
  변경   : <한두 줄 요지>
```
- **명시** = 대표님이 직접 정한 원칙 (발언을 인용). **추론** = 내가 사례에서 끌어낸 개선안.
  추론은 "추론"이라고 쓰고, 적용 조건을 좁게 잡는다.

## 6. 적용과 기록 (되돌릴 수 있게)

- 프로젝트 파일: 수정 후 커밋 `learn(IM-00N): <요지>`. 되돌리기 = `git revert <해시>`.
- 전역 파일(`~/.claude/…`, git 아님): 수정 **전** `~/.claude/backups/learn/<날짜>/` 로 복사. 되돌리기 = 복사본을 되돌려 놓기.
- 원장 `.claude/memory/learning/LEDGER.md` 에 항목 추가 (ID 는 `learn.py` 의 `next_im_id`):

```
### IM-00N · YYYY-MM-DD · applied|proposed|rejected|deferred|reverted
- 세션: <앞 8자리>
- 근거: 명시 ("<발언>") | 추론
- 신호: …
- 사례: …
- 적용 조건: …
- 변경: `<경로>` … (이전 상태: git <해시> | 백업 <경로>)
- 검증: …
- 평가: EV-00N (있으면)
```
- 결론이 뒤집히면 옛 항목을 지우지 않고 새 항목에 `supersedes: IM-00x`, 옛 항목 상태를 `reverted`.

## 7. 검증

- `python3 .claude/lib/learn.py lint` → error 0
- 고친 스킬·문서를 다시 읽어 조건·순서가 말이 되는지 확인
- 검사 스크립트를 만들었으면: **고치기 전 코드(git show)에서 실패하고 지금은 통과**하는지 확인
- 앱 테스트를 건드렸으면 전체 테스트 실행

## 8. 평가 — 대표 사례로 전후 비교

`.claude/memory/learning/evals/EV-00N-*.md` 에 사례 하나씩. 지표는 **기록에서 셀 수 있는 것만**:
- 대표님 지적·수정 횟수 (대화에서 셈 — 원장에 적어 둔다)
- 배포 후 fix 커밋 수 · 작업 소요 (`learn.py metrics --since … -- <경로>`)
- 완료 보고 뒤 발견된 결함 수
다음에 같은 조건의 작업을 하면 같은 지표를 적어 비교한다. 비교할 사례가 없으면 "비교 전"으로 둔다.
수치를 추정해서 채우지 않는다.

## 9. 정리 (낡음·충돌)

- `lint` 의 warn(재검토 기한 지남, superseded 가 INDEX 에 남음)과 info(트리거 겹침)를 본다.
- 겹치는 규칙은 **한 곳을 원본**으로 정하고 다른 곳은 포인터로 바꾼다 (삭제 대신 이동 — 확인 후).
- 낡은 사실은 확인 후 update, 결론이 뒤집혔으면 supersede ([[os-mem]] 규칙).
- 분기마다 `review_after` 가 지난 스킬을 훑는다.
