대표님 확정 (2026-09-24). 정산 대상 = round(총 판매금액 × 수수료율) — **부가세 포함 금액**으로 본다.

| 유형 | 실지급액 | 증빙 | 대상 100,000원 |
|---|---|---|---|
| 사업자 | 대상 전액 | 세금계산서 (공급가 90,909 + 부가세 9,091) | 100,000 |
| 간이사업자 | 대상 ÷ 1.1 (부가세만 뺌) | 현금영수증 | 90,909 |
| 프리랜서 | 대상 ÷ 1.1 에서 3.3% 원천징수 | 원천징수 | 90,909 − 3,000 = 87,909 |

원 단위 사사오입, 3.3% 는 한 번에 계산 (국세청식 3%+0.3% 10원 미만 절사와 10원 안팎 차이 — 대표님 표 기준으로 결정).
매출은 캠페인 **총 판매금액 하나**(제품·옵션 합계). 수수료율 자동: 캠페인 → 제품 → 인플루언서 기본값.

**흐름:** 작성중(pending) → 발행(confirmed, issued_at·계좌 저장) → 지급 완료(paid, paid_at). 발행 취소 가능, 지급 완료·발행된 건 삭제 불가.
내부 상태값은 그대로(대시보드·시트·포털 호환), 화면 이름만 변경. 실지급액 직접 입력 = `is_manual` → 자동 재계산이 덮지 않는다.
예전 계산식 행(`calc_version` NULL)은 금액 보존, 작성중이면 발행 때 "예전 → 새 금액" 확인 후에만 새 식 적용.

**근거 / 깨지면 어떻게 되는가:** 개편 전 계산식이 4곳(파이썬 2·JS 2)에 따로 있어 프리랜서 100,000원에 97,000 vs 87,030 이 나왔다.
**검증 방법:** `tests/test_settlements.py` (표 금액·흐름·수동·예전 행·회사 분리·한국 시간 월). 계산을 바꾸면 이 표부터 고친다.
**탈락 대안:** 예전 화면 계산(프리랜서 = 대상 − 공급가×3.3%, 97,000) — 부가세를 빼지 않음. 소싱 쪽 식(대상×0.9 − …, 87,030) — 부가세를 ÷1.1 이 아닌 ×0.1 로 뺌.
세무 판단은 세무사 확인 권장.
