## 2026-09-11

- **EC2 배포키 등록 → `deploy.sh git` 정석 경로 복구** ([[IS-002]] 해소 완료)
  왜: EC2 배포키가 GitHub 에 없어 `git pull` 이 막혀 있었고, 배포마다 `git archive`/bundle 우회가 필요했다.
  확인: EC2 에서 `git fetch origin` → OK, `git pull --ff-only origin master` → `7cd863b..6820fcb`
  fast-forward 성공. HEAD = origin/master, 추적파일 수정 0건. 받아온 커밋에 앱 코드가 없어
  재시작 생략. 라이브 `/` 302 · `/login` 200 · `/public/products` 200.

- **노출됐던 classic PAT 폐기 확인** — `api.github.com/user` 인증 → **HTTP 401**.
  GitHub classic 토큰 목록에는 만료본 2개만 남아 있고 해당 토큰은 없다(만료본도 목록에 남으므로
  "목록에 없다 = 삭제됨"). 커밋 이력에 들어간 적 없어 히스토리 재작성 불필요 ([[IS-002]]).

- **origin push 8커밋 + EC2 git 트리 드리프트 해소** (`e562af4` → `7cd863b`)
  왜: 로컬이 origin 보다 8커밋 앞서 있었고, EC2 는 그동안 scp 배포 탓에 git 상태가 실제 배포 내용과
  어긋나 `git pull` 이 충돌했다 ([[IS-002]]).
  어떻게: EC2 배포키가 GitHub 에 미등록이라 `fetch` 가 막혀 **`git bundle` 로 우회**했다.
  사전검증(동일 359 / 다름 2 / 없음 67) + 백업 `pre-reset-20260911-133536.tar.gz` 후 `reset --hard`.
  확인: 추적파일 수정 113 → **0건**, `app/` 코드 차이 0건이라 재시작 불필요,
  `.env`·`google_sa.json` 생존, `systemctl is-active` active, 에러 0건, `/login` 200 · `/public/products` 200.
  부수 발견: EC2 에만 있는 미추적 파일 9개 — 전부 미참조 잔재로 확인 ([[IS-004]]).
