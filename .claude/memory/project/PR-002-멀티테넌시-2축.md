격리 축이 **두 개**이고 서로 다른 장치를 쓴다. 하나만 챘다가 다른 쪽이 새는 사고가 반복됐다.

| 축 | 대상 | 장치 |
|---|---|---|
| `company_id` | 내부 사용자 (`/products` `/orders` …) | `app/auth/tenant.py::get_company_id(user)` |
| `partner_id` | 협력사 포털 (`/portal` …) | `app/services/portal_access.py` 의 `portal_context`/`PortalCtx` |

`get_company_id(user)`는 `user.company_id`가 `None`인 슈퍼어드민을 **company 1로 취급**한다.
약 29개 모델이 `company_id`를 갖고 27개 라우터가 이 헬퍼를 쓴다.

권한은 별개 층이다 — `app/auth/dependencies.py`의 `require_admin`/`require_super_admin`/
`require_manager`/`require_staff`/`require_partner`, 그리고 기능 플래그 `require_feature(key)`.
**권한 통과 ≠ 테넌트 격리.** 둘 다 걸어야 한다.

감사 도구: `tenant-scope-reviewer` 에이전트 (읽기 전용, 수정하지 않음).
