**"Find first, read second, edit third."** 전체 파일을 읽어야 할 명확한 이유가 없으면
필요한 범위만 읽는다 (`/os-locate` 절차).

- 정상 작동하는 기능은 건드리지 않는다. 한 기능 수정 때문에 무관한 UI/DB/API/스타일을
  재작성하지 않는다.
- **대규모 refactor 는 임의로 진행하지 않는다.** 이유와 영향범위를 먼저 설명하고 승인받는다.
- 수정 후 반드시 기록한다: 수정 파일 / 수정 위치 / 수정 이유 / 영향받는 기능 / 테스트 결과.
- 수정 전에 관련 regression 규칙(`.claude/memory/regression/`)이 있는지 확인하고,
  수정 후 그 조건을 확인한다.

주의: 이 프로젝트에는 **테스트가 없다**([[IS-001]]). 그래서 "테스트 통과"라고 말할 수 없는
상황이 대부분이다. 무엇으로 확인했는지를 정확히 적는다(셀프테스트 / import 검사 / 라이브 curl 등).
