**지킬 조건:** EC2 working tree 를 git 으로 정리(`git pull` / `reset --hard`)하기 전에
대상 커밋의 blob SHA 와 EC2 실제 파일의 `git hash-object` 를 **전수 비교**한다.
그리고 먼저 백업한다:
```bash
tar czf /home/ubuntu/deploy-backup-<stamp>.tar.gz --exclude='__pycache__' app scripts migrate.py
```

**깨지면 어떻게 되는가:** EC2 에만 있는 더 새로운 내용을 덮어써 잃는다. EC2 는 그동안 scp 로
배포돼 왔기 때문에 **git 상태가 실제 배포 내용을 알려주지 않는다**([[IS-002]]).

**실제 사례 (2026-09-10):** 커밋 메시지가 "운영 배포된 현행 상태 스냅샷"이라고 주장했지만
전수 비교 결과 **동일 350 / 다름 9 / 없음 36** 이었다. 샘플 5개만 봤을 때는 전부 일치해서
"동일하다"고 잘못 결론냈다. 다른 9개는 전부 운영이 더 오래된 쪽이었다.

**반드시 함께 확인:** `.env` · `google_sa.json` · `instagram_session.json` 이 git 에 추적되지
않는지 (`git ls-tree -r HEAD | grep ...`). 추적되면 `reset --hard` 가 운영 `.env` 를 덮어쓴다.
현재는 `.env.example` 만 추적된다(무해) — 확인된 사실.
