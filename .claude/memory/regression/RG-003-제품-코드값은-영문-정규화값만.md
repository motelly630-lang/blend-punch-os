**지킬 조건:** 별칭 정의의 단일 출처는 `app/services/product_service.py` 의
`_VISIBILITY_ALIASES` / `_STATUS_ALIASES` / `VISIBILITY_VALUES` / `STATUS_VALUES` 다.
저장은 **영문 소문자 정규화값**으로만 한다.

**깨지면 어떻게 되는가:** `/public` 은 `active` 또는 `NULL` 만 노출한다. 한글 `'공개'` 가 들어가면
**화면상 공개인데 공개 카탈로그에서 영구 누락**된다. 조용히 틀리므로 아무도 모른다.
2026-09-10 운영에서 실제로 4건이 누락돼 있었다 (`migrate.py` 가 `'공개' → 'active'` 로 정규화).

**특히 주의:** 엑셀 일괄 임포트가 한글 값을 다시 집어넣는 경로다. 런타임 정규화(소문자 기준)와
SQL 비교(`LOWER()`)가 어긋나면 `'Hidden'`/`'Active'` 같은 입력에서 두 경로 동작이 갈린다.

**검증 방법 (R2 — 읽기 전용 SQL):**
```sql
SELECT DISTINCT visibility_status FROM products WHERE visibility_status IS NOT NULL;
SELECT DISTINCT status FROM products WHERE status IS NOT NULL;
```
`VISIBILITY_VALUES`/`STATUS_VALUES` 밖의 값이 나오면 위반. `migrate.py` 가 재실행 시
미등록 값을 찾아 경고도 출력한다 (`! products.<col> 미등록 값 ...`).
