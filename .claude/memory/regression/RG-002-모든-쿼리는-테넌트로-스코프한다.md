**지킬 조건:** 내부 데이터 조회·수정·생성은 `cid = get_company_id(user)` 로 스코프한다.
협력사 포털은 `partner_id` 축을 따로 쓴다([[PR-002]]).

```python
cid = get_company_id(user)
order = db.query(Order).filter(Order.company_id == cid, Order.id == order_id).first()
```

**깨지면 어떻게 되는가:** 남의 회사 데이터가 보이거나 수정된다. 이 프로젝트에서 가장 비싼 버그
유형이고 **실제로 반복됐다**:
- `d92cb06` — `campaigns.py::_auto_settle` 이 자동 생성한 `Settlement` 에 `company_id` 누락
- 2026-09-09 `9f51957` — `campaigns.py` `import_products.py` `portal.py` `products.py` `public.py` 5건
- 스냅샷 커밋분 — `orders.py`(주문 임포트 조회), `settlements.py`(인플루언서 계좌 스냅샷)

**패턴:** 손으로 쓴 CRUD 보다 **자동 생성 경로**(서비스·에이전트·스케줄러·시트 임포트)에서
더 자주 빠진다. `db.add(...)` 로 새 행을 만드는 곳을 특히 본다.

**검증 방법 (R3 심사형):** `tenant-scope-reviewer` 에이전트로 변경분을 감사한다
(기본적으로 `git diff` 범위만 본다). 기계적 검사는 아직 없다 — [[IS-001]].
