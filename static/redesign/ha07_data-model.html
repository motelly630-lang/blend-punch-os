호텔 공동구매 — 데이터 구조 설계

확정된 정책 4가지 반영 · 기존 일반 공동구매 무수정 · 추가(additive) 원칙

설계 원칙

  • 기존 products·주문·정산 로직은 수정하지 않고 컬럼/테이블만 추가한다.
  • 상품유형은 products.product_type = 'normal' | 'hotel' 분기. 기존 데이터는 기본값 'normal'.
  • 호텔은 즉시 예약확정 + 날짜별 재고 차감 (목표인원 방식 아님).

2. 핵심 플로우

🔻 예약 확정 & 재고 차감 (즉시확정)

결제 승인 → 트랜잭션 안에서 투숙 각 날짜의 hotel_date_inventory.remaining을 -1 (2박이면 두 날짜 모두). 하나라도 remaining=0이면 예약 거부·환불. 목표인원 대기 없음.

💰 추가 인원 요금 계산

fee = COALESCE(inventory.extra_person_fee, rooms.default_extra_person_fee)
extra_person_amount = max(0, adults − base_capacity) × fee × nights
예) 기준2·추가2만, 성인3, 2박 → 1 × 20,000 × 2 = 40,000원

📥 엑셀 블록표 업로드

표준 컬럼(날짜·요일·객실타입·정상가·공구판매가·잔여객실·기준인원·최대인원·추가인원요금·비고) 파싱 → (room_id, date) upsert. 객실타입은 이름 매칭(없으면 신규 안내).
확장: hotel_column_mapping 프로파일 테이블을 추후 추가해 호텔별 컬럼명 매핑("객실명"→"객실타입") 지원.

🧮 정산 기준 전환

초기 settlement_basis='payment_date'로 settlement_date=payment_date. 호텔은 checkout_date를 함께 저장해 두므로, 향후 정책만 'checkout_date'로 바꾸면 settlement_date 재계산으로 즉시 전환.

3. API 엔드포인트 (초안)

메서드경로설명
GET/hotel/{product_id}호텔 상세 (H01)
GET/hotel/{id}/availability?ci=&co=기간 내 객실별 가격·잔여 (H02 달력·객실)
POST/hotel/{id}/reserve예약 생성 + 재고 차감 (트랜잭션)
POST/admin/hotel · /rooms호텔·객실 등록 (A1·A2)
POST/admin/hotel/{id}/inventory/upload엑셀 업로드 → upsert (A3)
PATCH/admin/inventory/{id}칸 클릭 수정(가격·잔여·추가요금) (A3)
POST/admin/inventory/bulk기간 일괄설정 (A3)
GET/admin/reservations예약 관리 (A4)
GET/admin/settlements?type=hotel&basis=정산 필터 조회 (A5)

확장 포인트 (초기엔 미구현, 구조만 대비)

  • hotel_column_mapping — 호텔별 엑셀 컬럼 매핑
  • settlement_basis='checkout_date' — 체크아웃일 기준 정산 전환
